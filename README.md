# 推しトラッカー (oshi_tracker)

推し(≠MEなど)の情報を定期収集して、1つの画面にまとめる個人用アプリ。

収集元:

| 情報源 | 内容 |
|---|---|
| 公式サイト(ニュース) | お知らせ・握手会・ライブ・メディア出演・グッズ情報 |
| 公式サイト(スケジュール) | 今月の予定(専用タブに、近い順で表示) |
| YouTube | 公式チャンネルの新着動画 |
| SHOWROOM | メンバーの配信開始 |
| Instagram / X / TikTok | スマホに届く公式の投稿通知を転送して記録([NOTIFICATION_SETUP.md](NOTIFICATION_SETUP.md)) |
| Instagram(直接取得) | メンバーの新規投稿。クラウドではほぼ機能しません(後述) |

TikTokもコードとしては残っていますが、ローカルで手動実行する場合のみ使う想定です
(詳しくは下記)。ニュース・動画のタイトルにメンバー名が入っていれば、自動でそのメンバーに
紐付けてメンバー別の絞り込みに反映します。

## 前提として知っておくこと

- 公式サイトとYouTubeは、認証なしで取得できる公開情報なので安定しています。
  ただしYouTubeのRSSは時々一時的に404や500を返すため、リトライを入れています
  (それでも失敗したら次回の実行で取り直します)。
- 公式サイトのスケジュールは、ページの構造上「今月分」しか取得できません。
- SHOWROOMは公開情報の取得なので比較的安定します。
- TikTokは公式APIが個人の情報収集に向いておらず、非公式ライブラリ(`TikTokApi`)
  を使っています。これは利用規約上グレーな手法で、**仕様変更で突然動かなくなる・
  アカウントが制限される可能性があります**。自己責任で、頻度を上げすぎずに
  使ってください。GitHub Actions(クラウド)側では収集していません(後述)。
- 以前はX(Twitter)も非公式ライブラリ(`twikit`)で収集していましたが、
  ログインが必要な方式でアカウント制限のリスクが高かったため廃止しました。
  現在このアプリはXの投稿を一切取得しません。
- GitHub Pages版([下記](#pcの電源が入っていなくてもスマホで見るgithub-pages)参照)を使う場合、
  収集した投稿本文・サムネイルはPublicなページとして誰でも見られる状態になります。
  ローカルのみで使う場合(`python webapp.py`)は自分のPC上だけに閉じます。
  いずれの場合も、収集した内容を自分の推し活以外の目的で転載・再配布しないでください。

## セットアップ

1. Python 3.11+ が必要です(このPCには3.12が入っています)。

2. 依存パッケージをインストール:
   ```bash
   pip install -r requirements.txt
   ```
   TikTokをローカルで使いたい場合は、`requirements.txt` 末尾のコメントアウトされた
   `TikTokApi` / `playwright` の行の `#` を外してから追加でインストールしてください:
   ```bash
   playwright install chromium
   ```

3. 設定ファイルを作成:
   ```bash
   cp config.example.yaml config.yaml
   cp .env.example .env
   ```

4. `config.yaml` はWeb検索で調べたメンバー情報を入れた状態で既に用意してあります。
   [ACCOUNTS.md](ACCOUNTS.md) のリンクを開いて、本人・公式のアカウントか確認してください。
   間違っていたら `config.yaml` を直接書き換えてください。新しく別の推しを追加する場合も
   同じ形式(`members:` の下に1ブロック追加)で書けます。
   - **SHOWROOM**: ルームURL `https://www.showroom-live.com/xxxxx` の `xxxxx` 部分
   - **Instagram**: `@` を除いたユーザー名
   - **TikTok**(ローカル実行専用): `@` を除いたユーザー名。使う場合のみ追加してください。

5. TikTokをローカルで使う場合は `.env` に認証情報を入れる(任意)。
   - `TIKTOK_MS_TOKEN`: ブラウザでtiktok.comにログイン→開発者ツール(F12)→
     Application タブ→Cookies→`ms_token` の値をコピー
   - **`.env` は絶対に他人と共有・公開しないこと。**

## 使い方

### 1回だけ収集する

```bash
python main.py
```

新しい投稿だけが `posts.db` (SQLite) に保存されます。

### ダッシュボードを見る

```bash
python webapp.py
```

ブラウザで http://127.0.0.1:5000 を開くと一覧が見られます。
画面上部の「メンバーで絞り込み」でメンバー別、プラットフォームのタブでSHOWROOM/Instagram別
(TikTokをローカルで使っている場合はTikTokも)に絞り込めます。

### スマホから見る

同じWi-Fiに繋いだPCとスマホなら、スマホのブラウザで
`http://<PCのIPアドレス>:5000` を開くと同じ画面が見られます。

PCのIPアドレスは以下で確認できます:
```bash
ipconfig
```
「IPv4 アドレス」(例: `192.168.0.16`) を使ってください。

**注意:** この方法はパスワードなどの認証が一切ない状態で画面を公開します。
自宅などの信頼できるWi-Fi内でのみ使い、カフェ等の公衆Wi-Fiでは使わないでください。
また `python webapp.py` を実行している間・PCがスリープしていない間だけアクセスできます。

スマホから繋がらない場合、Windowsのファイアウォールがブロックしている可能性があります。
初回 `python webapp.py` 実行時に「Windows セキュリティの重要な警告」が出たら
「プライベートネットワーク」にチェックを入れて「アクセスを許可する」を選んでください。

### 定期的に自動収集する(ローカルで動かす場合)

Windowsのタスクスケジューラに `python main.py` を好きな間隔で登録してください。
(例: 20分ごと)

## PCの電源が入っていなくてもスマホで見る(GitHub Pages)

PCを常時起動しておきたくない場合、収集(GitHub Actions)と表示(GitHub Pages)を
どちらも無料のGitHub上で動かす構成にできます。詳しい仕組みは
[.github/workflows/collect.yml](.github/workflows/collect.yml) と [docs/](docs) を参照。
クラウド側では公式サイト・YouTube・SHOWROOM・Instagramを収集します
(TikTokはローカル専用、Xは廃止済み)。

### セットアップ手順

1. GitHubのリポジトリ設定画面 → Settings → Actions → General →
   "Workflow permissions" で **"Read and write permissions"** を選んで保存
   (収集結果をリポジトリに書き戻すために必要)。

2. GitHubのリポジトリ設定画面 → Settings → Pages →
   "Build and deployment" の Source を **"Deploy from a branch"**、
   Branch を **`main` / `docs`** に設定して Save。
   数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセスできるようになります。
   このURLをスマホのホーム画面に追加しておくと、アプリのように使えます。

3. 初回は手動で1回動かして反映を確認できます:
   リポジトリの Actions タブ → "collect" ワークフロー → "Run workflow" ボタン。

### 注意点

- 更新は30分おきの自動実行(GitHub Actionsの仕様上、多少前後・遅延することがあります)。
- **Instagramは、実際にテストしたところGitHub Actions側のIPからは毎回100%
  レート制限(429)ではじかれることを確認済みです。** クラウド経由では
  Instagramの収集はほぼ機能しないと考えてください(ローカル実行なら問題ありません)。
- SHOWROOMは公開情報のみで比較的安定して動作します(実際に動作確認済み)。
- いずれかのプラットフォームで失敗しても、他のプラットフォームの収集は継続されます。
- `posts.db` はワークフロー実行のたびにコミットするとバイナリファイルでリポジトリが
  肥大化するため、コミットしません(`.gitignore` 済み)。代わりに、既にコミットされている
  `docs/data.json`(直近の投稿を含む)を毎回の実行開始時にDBへ読み込み直すことで、
  前回までの状態を復元しています。
- 収集データ(`docs/data.json`)と `config.yaml` はリポジトリにコミットされ、
  **リポジトリがPublicなので誰でも見られます**。`.env`(ログイン情報)は`.gitignore`で
  除外されており、コミットも公開もされません。

## スマホの通知を転送して Instagram / X / TikTok を拾う

これらはクラウドのIPからは取得できないため、各アプリがスマホに送っている
公式の投稿通知を拾ってGitHubに転送する方式をとっています。
スクレイピングではないので遮断されず、アカウントを預ける必要もありません。

設定手順は [NOTIFICATION_SETUP.md](NOTIFICATION_SETUP.md) にまとめてあります(Android専用)。

記録できるのは「誰が・どのアプリに・いつ投稿したか」とアプリへのリンクまでで、
**投稿本文や画像は通知に含まれないため入りません。**

## 収集元ごとの仕組みメモ

| プラットフォーム | 方式 | 安定性(ローカル) | 安定性(GitHub Actions) |
|---|---|---|---|
| 公式サイト | HTMLをスクレイピング (ログイン不要) | 高 | 高 |
| YouTube | 公式のチャンネルRSS (ログイン不要) | 中〜高(たまに一時エラー) | 中〜高 |
| SHOWROOM | 非公式の公開JSON API (ログイン不要) | 中 | 中 |
| Instagram | `instaloader` (公開プロフィールをログインなしで取得) | 中(レート制限あり) | 低(ほぼ常に失敗する) |
| TikTok | `TikTokApi` + Playwright (要ms_token、非公式) | 低 | 未対応(ローカル専用) |

うまく取得できないプラットフォームがあっても、他のプラットフォームの収集は継続されます。
